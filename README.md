# Two-Radius Facility Location on Unit Disk Graphs

Reference implementation of a **cut-based row-generation heuristic** for a
two-radius facility-location problem on a unit disk graph, together with the
**compact exact baseline** it is measured against, an automated experiment
driver, and a pytest suite.

The problem: place depots and charging stations in a planar service region so
that every demand point can be reached *from two different open depots by two
internally vertex-disjoint paths*, at minimum total opening cost.

---

## 1. The model

| Symbol | Meaning |
| --- | --- |
| `R` | flight radius, uniform for every tier (default `20`) |
| `r` | service radius, fixed to `r = R / 2` (default `10`) |
| `D` | number of demand points, each with requirement `k_p` |
| `F` | number of candidate charging stations |
| `k_p` | number of internally vertex-disjoint depot-to-demand paths required per demand |

* Facilities are placed in a fixed `100 x 100` square.
* An edge joins two facilities when their Euclidean distance is at most `R`.
  This is the **backbone** graph; demand points are *not* backbone vertices.
* A demand `p` can be served by a facility `v` when `dist(v, p) <= r`; those
  facilities form the **coverage set** of `p`.
* A design (a set of opened facilities) is feasible when, for every demand `p`,
  the opened backbone subgraph admits two internally vertex-disjoint paths from
  `p`'s coverage set to two **distinct** depots.
* Objective: minimise the sum of the opening costs of the selected facilities.

The two radii are deliberately separated because a service radius larger than
half the flight radius would make the "two disjoint paths" condition degenerate
in the disk geometry; the code enforces `2r <= R` and rejects instances that
violate it.

Instances are generated by rejection sampling: a facility layout is accepted
only when the facility graph, **with a virtual root joined to every depot**, is
two-root-connected at radius `R`. The `selectable` and `preinstalled` variants
of a tier share geometry, demands, requirements and station costs, which is
enforced through a SHA-256 fingerprint recorded in every result record.

## 2. The algorithm

**Stage 1 — deterministic weighted greedy set cover.** Builds an initial
feasible cover by repeatedly opening the facility with the best
cost-per-newly-covered-demand ratio, with two passes over the demands.

**Stage 2 — rooted set-pair residual LP with batch iterative rounding.** The
relaxation is the paper's rooted set-pair LP over the backbone edges
`E_2 = E_F u {{rho,w}: w in W}`: a pair of disjoint vertex sets `(U1,U2)` with
`Z = V_2 \ (U1 u U2)` carries the requirement
`q(U1,U2) = max({0} u {q_uv})` and the row
`sum_{e in E(U1,U2)} x_e >= g(U1,U2) = q(U1,U2) - |Z|`. The only nonzero
requirements are `(rho,t)` with `r_t in {1,2}`, so every set pair is compiled
by the single entry point `compile_setpair_row`.

Each round fixes `J` (the edges already rounded), keeps only `E_2 \ J` as
variables and subtracts the fixed crossing contribution from every right-hand
side (`residual_mode = eliminate_fixed_edges`). For every terminal a
*split-graph* threshold minimum cut is computed on that residual model; one
max-flow yields **two** candidate rows (a double cut: the smallest and the
largest minimum cut on the source side), which is what makes the method
converge in a handful of rounds instead of dozens. The separator returns set
pair *evidence* only; the master LP is re-solved with the dual simplex to an
optimal **basic** point and every edge with `x_e >= 1/2` is fixed to `1` at
once (batch rounding). The rounded design is then tested for
two-root-connectivity and reduced with reverse-delete. The rounding test is
performed on the full graph, so the loop terminates on a verified-feasible
design.

`--cut-mode` selects the row policy: `single`, `double` (default; fastest in
the ablation), or `nested`. `--separator-backend` selects the max-flow engine
(`scipy` sparse-graph maximum flow, or a pure-Python Dinic implementation).
Every CPLEX row can be traced back to `(U1, U2, Z, q, g, J)`; the per-case CSV
records `formulation = rooted_set_pair_lp`,
`formulation_version = explicit_residual_v1`,
`residual_mode = eliminate_fixed_edges`, `separation_backend`,
`setpair_witnesses_added`, `stage_two_max_violation`,
`stage_two_rebuild_seconds` and `scaling_fallback_calls`.

## 3. The baseline

`baseline.py` builds the **compact node-capacitated multi-commodity FLOW-IP**
for the same instance and solves it with CPLEX:

* the first node-0 relaxation value is read straight out of the node log of the
  same MIP solve — there is deliberately no separate FLOW-LP solve;
* the comparison therefore uses the FLOW-IP itself: its optimum when it proves
  optimality, and otherwise CPLEX's final best bound, reported as
  `certified gap upper bound` against `ip.best_bound`
  (`ip_lower_bound_basis = final_ip_lower_bound`);
* solving the standalone LP relaxation of the *same* rows, columns and
  coefficients is **off by default** (`--lp-fill-max-stations -1`): on the
  larger tiers that LP has millions of columns and its barrier + crossover tail
  ran to the time limit without a bound, while the IP with its root cut loop
  closed the same root gap in minutes. Passing a non-negative tier size
  re-enables the backfill, and the certified lower bound becomes
  `max(final MIP best bound, LP relaxation)`. Both are valid lower bounds, so
  taking the maximum can never overstate the solution quality;
* if the estimated variable count exceeds `MAX_FLOW_IP_VARIABLES`, the model is
  skipped with reason `model_too_large` instead of exhausting memory.

Quality is reported two ways, and the report keeps them apart on purpose:

* `quality_gap_basis = "exact_ip_optimum"` — the FLOW-IP proved optimality, so
  `algorithm_exact_gap_percent = 100 * (U / OPT - 1)` is an exact relative error;
* otherwise `quality_gap_basis` names the bound used and
  `algorithm_certified_gap_upper_percent` is a **certified error upper bound**.

## 4. Project layout

```
orl-two-radius-setpair/
├── main.py          # CLI entry point: choose scales, seeds, variants -> run -> write results
├── instance.py      # constants, TwoRadiusInstance, rejection-sampling generator
├── algorithm.py     # Stage 1 + Stage 2 (set-pair compiler, split-graph separator, rounding, verification)
├── baseline.py      # FLOW-IP, its LP relaxation, the node model, CPLEX log parsing
├── experiment.py    # one case, the quality metrics, summary rows and file writers
├── conftest.py      # makes the flat modules importable when pytest runs from the root
├── tests/           # pytest suite (instance, algorithm, baseline, experiment, CLI)
├── legacy/          # the original single-file implementation, kept for reference
├── requirements.txt
└── pyproject.toml   # pytest configuration
```

The modules are intentionally flat so each file can be read on its own; the
dependency direction is always `instance <- algorithm <- baseline <- experiment
<- main`.

## 5. Installation

CPLEX is a hard requirement — the FLOW-IP baseline and the Stage-2 master LP are
both solved through its Python API, and there is no free-solver fallback.

```bash
# 1. install IBM ILOG CPLEX Optimization Studio 22.1 and make the Python API
#    importable in your interpreter
python -c "import cplex; print(cplex.Cplex().get_version())"

# 2. install the remaining dependencies
pip install -r requirements.txt
```

Verified with CPLEX 22.1.1.0, Python 3.10.0, on Windows 10.

## 6. Running an experiment

```bash
# one pilot tier, one repetition
python main.py --scales 5,50,25 --seeds 101 --variants selectable

# a custom grid: two tiers, both variants, three repetitions
python main.py --scales 5,50,25 10,100,50 --seeds 101 102 103

# the full pre-registered experiment (5 tiers x 2 variants x 5 seeds = 50 cases)
python main.py
```

`--scales` takes `depots,stations,demands` triples and `--seeds` takes the
number of repetitions. Everything else has a default:

| Option | Default | Purpose |
| --- | --- | --- |
| `--scales` | `(5,50,25) (10,100,50) (20,200,100) (30,300,150) (50,500,250)` | instance tiers |
| `--seeds` | `101 102 103 104 105` | repetitions per tier and variant |
| `--variants` | `selectable preinstalled` | depot variants |
| `--flight-radius` | `20.0` | `R`; the service radius is `R/2` |
| `--side` | `100.0` | side length of the square region |
| `--max-facility-draws` | `500` | rejection-sampling budget |
| `--separator-backend` | `scipy` | `scipy` or `python` min-cut engine |
| `--cut-mode` | `double` | `single`, `double`, or `nested` |
| `--epsilon` | `0.20` | Stage-1 cover slack |
| `--time-limit` | `1800.0` | separate limit for the algorithm and for the FLOW-IP |
| `--skip-ip-stations` | `0` | skip the FLOW-IP for tiers with at least this many stations |
| `--lp-fill-max-stations` | `-1` | only solve the standalone LP relaxation up to this tier; `-1` (default) never solves it, `0` means no limit |
| `--output` | `output/orl_two_radius_results.jsonl` | result path |
| `--resume` | off | continue a matching partial run, skipping completed cases |
| `--fill-lp` | off | post-process an existing result file and add missing LP relaxations |

`--resume` compares the stored experiment signature before continuing, so a
resumed run can never silently mix two different parameter sets. Because the
generator is deterministic, re-running a tier and seed with a different solver
option reproduces the identical instance.

## 7. Output

Every run writes four artifacts next to `--output`:

| File | Content |
| --- | --- |
| `<stem>.jsonl` | one JSON record per case, appended case by case, with the full instance, generator metadata, both solutions and all timings |
| `<stem>.csv` | one row per case, flat enough to open in a spreadsheet |
| `<stem>_table_summary.csv` | the aggregated main table: one row per (tier, variant, requirement mode, cut mode) with means and maxima |
| `<stem>_settings.json` | the parameters, the environment (Python, CPLEX, networkx, platform, CPU count), the method description and the expected case count |

The per-case CSV reports, among others: the algorithm cost `U`, the FLOW-IP
objective and status class, the lower bound actually used and its basis, the
exact relative error or certified error upper bound, the Stage-1/Stage-2 cost
split, the number of master LP solves, the number of retained cuts, and the
`case_seconds` / `algorithm_seconds` / `ip_seconds` timings. Status classes are
`optimal`, `open_gap`, `no_incumbent`, `invalid_incumbent`,
`skipped_too_large` and `skipped_by_request`.

## 8. Tests

```bash
pytest
```

The suite checks the instance model and its invariants, the cut oracle against
a hand-computed minimum cut, the two-stage algorithm against a brute-force
optimum on a tiny instance, the FLOW-IP / LP relaxation / node model agreement,
the quality-metric branches, the CSV/aggregation writers, and one end-to-end CLI
pilot run (including the overwrite guard and `--resume`).

`--capture=no` is *not* needed: `baseline._CapturedSolverLog` redirects both the
Python stream and the process descriptors, so the CPLEX node log is captured
correctly under pytest's own stdout capture.

## 9. Results and limitations

On the pre-registered tiers every reported design passes the independent
two-root-connectivity verification, and up to 300 stations the algorithm lands
within a few percent of the CPLEX optimum. The root relaxation of the compact
FLOW-IP on unit disk graphs is very tight, so CPLEX is hard to beat at small
sizes; the advantage of the cut-based method appears as the instance grows,
where each row-generation round costs far less than re-solving the compact
model.

At 500 stations the compact FLOW-IP (and, on the reference machine, even its LP
relaxation) exceeds what CPLEX can handle: the model reaches millions of columns
and the barrier factorisation no longer fits in memory, while the dual simplex
and sifting stall. Such tiers are therefore recorded as skipped
(`ip.status_class = "skipped_by_request"`) with the reason stored in the JSONL,
and no exact optimum is reported for them.

The known limitation is exactly this asymmetry: large tiers have no certified
optimum, so their quality is only bounded by the LP relaxation, which may be
loose.
